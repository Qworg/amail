# GitHub Next Research Engineer: Take Home Exercise

Hi there! I'm Idan, and I'm asking you to do this little project as a prelude to our interview, so that we can talk more about how things get built and less about "describe a time when…"

The goal is for you to build a small thing that we can discuss. **You should spend 3–5 hours at most.** Our expectations are calibrated for that amount of effort.

## Instructions

Build a small tool that supports or accelerates your own engineering workflow — and make it something your coding agent can use, not just you. (Note: You should use whatever agent(s) you usually do; don't switch tools/agents just for this project.)

Form is up to you: an MCP server, a CLI, a skill, a hook, something we haven't thought of. The only real constraint is that we can run it, or watch you run it.

Agent-usable doesn't mean agent-only. If the right answer involves a surface a person can see or steer — a view, a review step, something you and your agent look at together — that's fair game.

Designing for an agent is a different job than designing for a person, and we're interested in how you approach that difference.

Aim for modest genuine utility. The best submissions tend to be things you actually wanted to exist before we asked.

## How you work is part of what we're discussing

Use your normal development practices, including whatever AI and agents you'd normally reach for. This is not a "coding" or algorithm design interview. Do come prepared to talk about your workflow: how you drove the work, what you verified, what you reviewed, and where you decided the quality bar was. If you have a transcript or session log from building it, bring that along — it makes for a much more concrete conversation than memory does.

## Do's and Don'ts

- ✅ **Do** finish. Done and modest beats ambitious and broken.
- ✅ **Do** cut scope aggressively — we'd rather hear why you cut something than see it half-built.
- ✅ **Do** be ready to share your screen and walk through the code.
- ✅ **You can** open-source it if you like. Though if it's polished enough to release, you probably spent too long.
- 🚫 **Do not** just wrap an API and hand the agent the raw response. That's a proxy, not an interface.
- 🚫 **Do not** let a UI eat the whole budget. If you build one, leave time to see whether it actually helps.
- 🚫 **Do not** worry about code quality or polish. Code written in a few hours looks like it, and that's fine.
- 🚫 **Do not** spend too much time on this. Seriously.
